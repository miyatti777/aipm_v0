## 2. リスク評価基準

### 影響度

| レベル | 定義 |
|--------|------|
| **最高** | プロジェクト中止・大幅な予算超過・法令違反 |
| **高** | スケジュール1ヶ月以上遅延・主要機能の利用不可 |
| **中** | スケジュール2週間以内の遅延・一部機能の制限 |
| **低** | 軽微な影響・ワークアラウンドで対応可能 |

### 発生確率

| レベル | 定義 |
|--------|------|
| **高** | 70%以上（ほぼ確実に発生する） |
| **中** | 30〜70%（発生する可能性がある） |
| **低** | 30%未満（起こりにくい） |

### リスクスコア = 影響度 × 発生確率

| | 影響度 低 | 影響度 中 | 影響度 高 | 影響度 最高 |
|---|:---:|:---:|:---:|:---:|
| **確率 高** | 中 | 高 | 最高 | 最高 |
| **確率 中** | 低 | 中 | 高 | 最高 |
| **確率 低** | 低 | 低 | 中 | 高 |

## 3. リスク登録簿

### R1: 従業員の利用定着が進まない

| 項目 | 内容 |
|------|------|
| **リスクID** | R1 |
| **カテゴリ** | 組織・チェンジマネジメント |
| **影響度** | 高 |
| **発生確率** | 中 |
| **リスクスコア** | 高 |
| **リスクオーナー** | PM |
| **影響の詳細** | 導入しても旧方式で申請する従業員が多く、並行運用が長期化。経理負荷が増大 |
| **対策（軽減）** | ①丁寧なトレーニング（部署別） ②分かりやすいマニュアル・動画 ③部門チャンピオン制度 ④ヘルプデスクの設置 |
| **対策（回避）** | パイロット期間で課題を洗い出し、全社展開前に改善 |
| **トリガー** | パイロット期間中の利用率が80%未満 |
| **コンティンジェンシー** | 追加トレーニング実施、個別フォロー強化、展開スケジュール延期 |
