## 3. 課題とソリューションの対応

| 課題（Problem） | ソリューション（Solution） | 期待効果 |
|----------------|--------------------------|---------|
| Excel手入力が面倒（20分/件） | OCR読取＋自動入力 | 5分/件に短縮（75%削減） |
| 勘定科目が分からない | AI自動判定 | 科目ミスによる差戻し80%減 |
| 領収書の紛失 | スマホ撮影＋即時電子保存 | 紛失率0% |
| リモート時に申請不可 | クラウド＋モバイル対応 | 場所を問わず申請可能 |
| 外出時に承認不可 | スマホアプリ承認 | 移動中でも承認可能 |
| 経理の手作業照合（15分/件） | 自動マッチング＋バリデーション | 3分/件に短縮（80%削減） |
| 仕訳の手入力ミス | 仕訳自動生成 | 転記ミス0件 |
| 月末残業の常態化 | 随時処理＋自動化 | 残業50%以上削減 |
| 紙保管スペース不足 | 電子保存 | 物理保管不要 |
| 電帳法未対応 | 標準機能で電帳法完全対応 | コンプライアンスリスク解消 |

## 4. 導入アプローチ

### 4.1 フェーズ分け

| フェーズ | 期間 | 内容 | 対象 |
|---------|------|------|------|
| **Phase 0: 準備** | 2026年3月 | 契約、環境設定、マスタ設定 | PM・経理・情シス |
| **Phase 1: パイロット** | 2026年4月〜5月 | 1〜2部署での先行導入 | パイロット部署 |
| **Phase 2: 改善** | 2026年5月後半 | フィードバック収集・改善 | PM・経理 |
| **Phase 3: 全社展開** | 2026年6月 | 全従業員への展開 | 全社 |

### 4.2 移行方式

| 項目 | 方針 |
|------|------|
| **切替方式** | 段階的移行（パイロット→全社） |
| **並行運用** | パイロット期間中のみ旧方式と並行（最長1ヶ月） |
| **データ移行** | 過去データの移行は行わない（新規申請からバクラク精算を利用） |
| **旧システム停止** | 全社展開完了後、翌月から旧方式を完全停止 |
